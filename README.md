# ឃ្លានញ៉ាំ (Klean Nham) – Cambodian food search (RAG chatbot)

Ask for a dish, a place or a time in English or Khmer, and get places in Phnom Penh. Hybrid search (BM25 + multilingual
embeddings) retrieves places from our list; an AI model (Gemini, or Ollama) writes a short answer using only those rows.
Available as a website, a Telegram Mini App and a Telegram bot, plus a "How it works" demo page.

```
[ data_preprocessing.ipynb ]  collect and clean the places  ->  data/restaurants.csv
            │
            ▼
[ food_search.ipynb ]         indexing, BM25 + embeddings (ChromaDB), evaluation, RAG, bot
            │  section 9 "Export" writes the backend
            ▼
[ backend/  (FastAPI + bot) ] ──JSON API──▶ [ frontend/  (React) ]   chat app, Telegram Mini App, demo
```

## Changing the backend

1. Edit the code in **`food_search.ipynb`, section 9 (Export)**: one cell per backend file.
2. Run the whole section. It writes `backend/`, `requirements.txt` and the `Dockerfile`; every generated file starts with
   a line saying so. A file it replaces is first saved in `export_backups/<date_time>/`, so nothing is lost.
3. Restart `python backend/web.py` (or `python backend/bot.py`).

The frontend is a separate app: edit `frontend/src/` directly.

## Dish photos and recipes (ML part)

Send a food photo: the app names the dish (one of the 101 [Food-101](https://data.vision.ee.ethz.ch/cvl/datasets_extra/food-101/)
dishes), shows its recipe (prep / cook / total time, ingredients, steps) and the places that serve it. Then ask
“how do I make it?”, “how long does it take?”, “what are the ingredients?” or “where can I eat it?”.

1. **Train** `food_classification.ipynb` on Kaggle or Colab (free GPU, ~2 h; instructions at the top of the notebook).
   It compares a small CNN from scratch, EfficientNet-B0 (transfer learning) and CLIP zero-shot, and writes the
   figures and tables for the report to `results/food_classification/`. Copy `models/food101_efficientnet_b0.pt` into
   `models/`. Until then the app uses CLIP zero-shot, so photos already work.
2. **Recipes**: `data/recipes.csv` is built by `python scrapers/recipes_foodcom.py` (needs `pip install pyarrow`;
   downloads ~450 MB of Food.com recipes into `data/raw/foodcom/`). 99 of the 101 dishes have a recipe; Food.com has
   no proper sashimi or takoyaki recipe, and the app says so.
3. **Learning from users**: when an answer is wrong, the user taps **`/correction`** (Telegram menu, or the `/`
   command menu in the web chat) and then just types the right answer: the next message is the correction, no second
   `/correction` needed (“cancel” skips it). In one go also works: `/correction amok`. Or tap the right dish under
   “Not it?”, or type “no, it's amok”.
   * After a photo: the app remembers that photo's fingerprint at once (that photo sent again gets the right dish
     from then on; someone else's correction only counts for a near-identical photo) and saves the photo in
     `data/feedback/` (git-ignored, no user names). `food_classification.ipynb` trains on these photos next time
     (`use_feedback`); its section 9 measures the effect. A dish the app does not know yet is saved for training only.
   * After a text answer (“/correction this place closed last year”): saved with the question and the answer, shown
     to that user when they ask again, and to everyone once approved.

   Review with `python scrapers/feedback_review.py` (`--list`, `--approve ID`, `--remove ID`); `/deleteme` in the bot
   removes a user's own corrections.

## Run

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # then fill in TELEGRAM_TOKEN, GEMINI_API_KEY, LLM_MODELS, ...

cd frontend && npm install && npm run build && cd ..     # build the website once (and after frontend changes)
python backend/web.py                                     # http://127.0.0.1:8080
```

| What | Command | Open |
|---|---|---|
| Website + API + demo + bot | `python backend/web.py` | http://127.0.0.1:8080 |
| Website only (bot runs elsewhere) | `RUN_BOT=0 python backend/web.py` | http://127.0.0.1:8080 |
| Telegram bot only | `python backend/bot.py` | your bot in Telegram |
| Frontend with live reload | `cd frontend && npm run dev` (with `web.py` running) | http://localhost:5173 |
| Docker (builds the frontend too) | `docker build -t food-bot . && docker run --env-file .env -p 8080:8080 food-bot` | http://localhost:8080 |

Pages: `/` the chat app, `/demo` how answers are made (the 3 steps, retrieved rows, prompt, BM25 vs embeddings, data),
`/docs` API documentation. Only one process may poll a bot token at a time, so do not run `backend/bot.py` and
`backend/web.py` (with the bot) together.

**AI models:** `LLM_MODELS` in `.env` lists the models users can choose from (first = default), e.g.
`gemini:gemini-3.5-flash-lite,gemini:gemini-3.6-flash`. If the chosen one is busy, the next one answers.

**Local model (Ollama + Qwen, free and unlimited, runs on this Mac):**

```bash
brew install ollama && brew services start ollama   # Ollama runs in the background, also after a restart
ollama pull qwen3.5:4b                              # 4 GB; qwen3.5:9b (7.6 GB) answers better but slower
```

then add it to `.env`, e.g. as the second model so it answers whenever Gemini is busy or out of free quota:
`LLM_MODELS=gemini:gemini-3.5-flash-lite,ollama:qwen3.5:4b=Qwen 3.5 4B (local),...` and `OLLAMA_MODEL=qwen3.5:4b`.
Users can also pick it in the model menu (web) or with `/model` (Telegram). Deciding what a message needs (follow-up
or new search) always uses the default model when it is available; the chosen model writes the answer.

## Telegram Mini App

Telegram opens Mini Apps over HTTPS only. Put `backend/web.py` behind HTTPS (a server, Cloud Run, or a tunnel such as
`ngrok http 8080`), set `WEBAPP_URL=https://…` in `.env` and restart: the bot then shows an **Open app** button.

Bot profile picture: send `frontend/public/bot-avatar.png` to @BotFather with `/setuserpic`.
